# Мелотрек

Інструмент для проведення музичного квізу «Мелотрек»: організатори збирають програму з YouTube-посилань, програма сама завантажує відео, нарізає фрагменти й показує все на проєкторі, а ведучий керує показом з телефона. Команди реєструються через QR-код, бали вносять прямо в програмі, а в кінці на екрані оголошують переможців.

## Як це працює

1. **Мелотрек** — окрема подія (наприклад, «Мелотрек 27 вересня»). Мелотрек можна скопіювати як шаблон, і пісні та кліпи перейдуть одразу.
2. **Категорії** — теми раундів, у кожній кілька **пісень**.
3. **Пісня** — це посилання на YouTube. Можна вставити одразу кілька посилань, по одному в рядку. Після додавання:
   - назва й обкладинка підтягуються з YouTube, відповідь заповнюється як «Виконавець — Назва»;
   - відео завантажується у фоні (прогрес видно в списку);
   - фрагмент (за замовчуванням перші 15 с) нарізається автоматично. Після кожної зміни часу, рамки чи гучності він переріжеться сам, кнопка «рендер» більше не потрібна.
   Гучність усіх фрагментів вирівнюється (EBU R128), на початку й у кінці фрагмента звук плавно наростає і згасає.
4. **Команди** додаються вручну або самі: відкрийте реєстрацію, і на вітальному екрані з'явиться QR-код.
5. **Показ.** «Екран» відкривають на комп'ютері з проєктором, «Пульт» — на телефоні. Далі все йде автоматично: назва категорії → відлік 3-2-1 → пісня → час на відповідь → наступна пісня… Після категорії показ зупиняється на екрані «Здаємо бланки / готуємо відповіді», а ведучий відкриває правильні відповіді.
6. **Оцінювання.** Перевіряльники ставлять ✓ / ✗ / ½ у таблиці, там же нараховуються бонусні чи штрафні бали; кілька людей можуть працювати одночасно. Результати глядачі бачать лише у фіналі.
7. **Фінал.** Екран «Підраховуємо бали…», потім переможців оголошують по черзі: спершу всі місця нижче п'єдесталу, далі 3-тє, 2-ге і 1-ше, з конфеті.

Екран оформлюється однією з трьох тем: **Неон** (синтвейв), **Вініл** (теплий ретро-лаунж) або **Сцена** (концертні прожектори). Тему можна перемкнути будь-коли на вкладці «Показ».

### Керування показом

| Дія | Пульт | Клавіатура |
| --- | --- | --- |
| Почати / далі | велика кнопка | `Пробіл`, `→` |
| Назад | «Назад» | `←` |
| Пауза / продовжити | «Пауза» | `P` |
| Програти пісню ще раз | «Ще раз» | `R` |
| Перемотати таймер | «−5 с / +5 с» | |
| Перейти до категорії чи результатів | «Перейти до…» | |

Показ веде сервер: усі екрани й пульти бачать один і той самий стан, а якщо телефон ведучого втратить зв'язок, екран продовжить сам. Після перезапуску сервера показ відновлюється на тому ж місці (на паузі).

## Запуск у Docker (рекомендовано)

Потрібні лише Docker і Docker Compose. У образі вже є ffmpeg, yt-dlp і Deno (його потребує yt-dlp для YouTube).

```bash
cp .env.example .env      # впишіть APP_PASSWORD і JWT_SECRET
docker compose up -d --build
```

Сайт відкриється на `http://сервер:8080`. Уся база та медіа лежать у теці `./data`: її й треба бекапити.

Під час кожного старту контейнер оновлює yt-dlp: YouTube регулярно ламає старі версії, і це найчастіша причина помилок завантаження. Щоб оновити вручну, просто перезапустіть контейнер: `docker compose restart`.

Для HTTPS поставте перед сервером будь-який reverse proxy (Caddy, nginx) і задайте `SECURE_COOKIES=true`. Приклад для nginx (сервер із застосунком може бути й іншою машиною, наприклад у WireGuard):

```nginx
server {
    server_name melotrack.example.com;
    # listen 443 ssl; ssl_certificate … — як у решті ваших сайтів

    client_max_body_size 2g;            # ручне завантаження відео (MAX_UPLOAD_MB)

    location / {
        proxy_pass http://10.0.0.148:8080;
        proxy_set_header Host $host;    # обовʼязково: без цього WebSocket відхиляється
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;         # WebSocket (показ і живі оновлення)
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 1h;
        proxy_request_buffering off;    # великі файли йдуть одразу на сервер
    }
}

# у блоці http { }:
map $http_upgrade $connection_upgrade { default upgrade; '' close; }
```

Із `SECURE_COOKIES=true` увійти можна лише через HTTPS. Якщо відкривати сервер напряму за `http://…:8080`, сесія не збережеться. Для перевірки в локальній мережі тимчасово поставте `false`.

## YouTube на VPS

YouTube часто блокує завантаження з IP-адрес дата-центрів: з'являється помилка «Sign in to confirm you're not a bot» або 403. Програма розпізнає ці помилки й пише в інтерфейсі, що сталося. Назви й обкладинки це не зачіпає: вони беруться з oEmbed та `i.ytimg.com`, які не блокуються.

Способи обійти блокування, від найпростішого:

1. **Свіжий yt-dlp.** Docker-образ оновлює його сам. Якщо YouTube щойно щось змінив, увімкніть нічні збірки: `YTDLP_NIGHTLY=true`.
2. **Файл вручну.** У вікні пісні натисніть «Замінити файлом з комп'ютера». Цей спосіб працює завжди. Файл можна скачати будь-де (наприклад, тим самим yt-dlp на своєму ноутбуці), а сервер перекодує його й наріже фрагмент. Пісні, яких немає на YouTube, додаються кнопкою «З файлу».
3. **Тунель через домашній комп'ютер (безкоштовно).** Завантаження піде через домашній інтернет, який YouTube не блокує. На домашньому комп'ютері (Linux, macOS або Windows 10+ з вбудованим OpenSSH) запустіть:
   ```bash
   ssh -N -o ServerAliveInterval=30 -R 1080 user@ваш-vps
   ```
   Це відкриває SOCKS-проксі на `127.0.0.1:1080` на VPS. Щоб контейнер його бачив, запустіть сервіс у мережі хоста, додавши в `docker-compose.yml`:
   ```yaml
   services:
     melotrack:
       network_mode: host   # замість ports:
   ```
   і в `.env`: `YTDLP_PROXY=socks5://127.0.0.1:1080`. Тунель потрібен лише тоді, коли додаєте пісні. Для стійкого з'єднання підійде `autossh`.
4. **Cookies акаунта YouTube.** Заведіть окремий Google-акаунт і увійдіть у YouTube в приватному вікні. Експортуйте cookies у форматі Netscape (наприклад, розширенням «Get cookies.txt LOCALLY») і закрийте вікно, не виходячи з акаунта. Покладіть файл у `./data/cookies.txt` і задайте `YTDLP_COOKIES=/data/cookies.txt`. Акаунт теоретично можуть заблокувати, тому основний не використовуйте.
5. **PO-token провайдер** (експериментально, окремо не перевірявся): `docker compose --profile pot up -d`, а в `.env`:
   ```
   YTDLP_POT_PROVIDER=true
   YTDLP_EXTRA_ARGS=--extractor-args youtubepot-bgutilhttp:base_url=http://pot-provider:4416
   ```
6. **Платний резидентський проксі** — `YTDLP_PROXY=http://user:pass@host:port`.

Стан yt-dlp (версія, чи налаштовано проксі або cookies) видно на вкладці «Показ» → «Сервер».

## Перехід зі старої версії

Під час першого запуску нова версія сама переносить дані старої:

- перед міграцією база копіюється в `<файл бази>.pre-v2.bak`;
- проєкти, категорії, пісні (з часом, обрізанням і гучністю) та фото відповідей переходять у нову схему;
- відео з `./downloads/raw` копіюються в `./data/media`, а кліпи нарізаються заново автоматично. Чого немає на диску, те завантажиться знову.

Старий `.env` теж підходить: якщо `APP_PASSWORD` не задано, для входу використовується `ADMIN_PASSWORD`. Ролей більше немає, вхід відбувається одним паролем. Коли переконаєтесь, що все на місці, теку `downloads/` можна видалити.

## Розробка

Потрібні Go 1.26+, Node 24+, ffmpeg, yt-dlp і deno.

```bash
cp .env.example .env
go run ./cmd/melotrack            # API на :8080
cd frontend && npm install && npm run dev   # інтерфейс на :5173 з проксі на API
```

Перевірки:

```bash
go test ./internal/...
cd frontend && npm run lint && npm run build
```

### Структура

```
cmd/melotrack      точка входу: конфіг, міграції, воркери, HTTP-сервер
internal/config    змінні середовища
internal/store     схема SQLite, міграції (включно з імпортом старої версії), моделі
internal/auth      вхід за паролем, сесія в HttpOnly-cookie
internal/media     yt-dlp, ffmpeg, метадані YouTube, черги завантажень і нарізки, прибирання файлів
internal/game      стан показу (чиста машина станів + сесія з таймерами)
internal/live      WebSocket-хаб: стан показу й живі оновлення для редакторів
internal/api       REST API, роздача файлів і фронтенду
frontend/src       React: project/ — редактор, show/ — екран і пульт, pages/ — сторінки
```

Уся фонова робота відновлюється з бази, а не з пам'яті, тож перезапуск нічого не губить. Кліп прив'язаний до налаштувань ключем (хешем часу, рамки, гучності й версії джерела), тому застарілий фрагмент видно одразу, а неактуальні файли прибираються самі.

### Змінні середовища

| Змінна | За замовчуванням | Опис |
| --- | --- | --- |
| `APP_PASSWORD` | — | пароль організаторів (обов'язково) |
| `JWT_SECRET` | — | секрет для сесій, від 16 символів (обов'язково) |
| `PORT`, `HOST` | `8080`, `0.0.0.0` | адреса сервера |
| `DATA_DIR` | `./data` | база й медіа |
| `DATABASE` | `DATA_DIR/melotrack.db` | шлях до файлу SQLite |
| `SESSION_TTL` | `168h` | тривалість сесії (продовжується під час роботи) |
| `SECURE_COOKIES` | `false` | `true` за HTTPS |
| `CLIP_HEIGHT` | `720` | якість кліпів: 480, 720 або 1080 |
| `DOWNLOAD_WORKERS`, `RENDER_WORKERS` | `2`, `1` | паралельність |
| `MAX_UPLOAD_MB` | `2048` | ліміт ручного завантаження |
| `YTDLP_PROXY` | — | проксі для YouTube |
| `YTDLP_COOKIES` | — | шлях до cookies.txt |
| `YTDLP_EXTRA_ARGS` | — | додаткові аргументи yt-dlp |
| `YTDLP_AUTO_UPDATE` | `true` | (Docker) оновлювати yt-dlp під час старту |
| `YTDLP_NIGHTLY` | `false` | (Docker) нічні збірки yt-dlp |
| `ALLOWED_ORIGINS` | `http://localhost:5173` | додаткові origin-и для WebSocket (dev-сервер) |
